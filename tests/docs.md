# Noridoc: tests

Path: @/tests

### Overview

The test suite exercises [wmviz/trace/](wmviz/trace/docs.md), the CLI ([wmviz/cli.py](wmviz/cli.py)), the no-Blender preview/aggregate/compositing layer ([wmviz/preview.py](wmviz/preview.py), [wmviz/mpl.py](wmviz/mpl.py), [wmviz/compose.py](wmviz/compose.py), [wmviz/aggregate.py](wmviz/aggregate.py)), and the Blender layer ([wmviz/scene/](wmviz/scene), [wmviz/animate.py](wmviz/animate.py), [wmviz/cameras.py](wmviz/cameras.py), [wmviz/overlays.py](wmviz/overlays.py), [wmviz/render.py](wmviz/render.py)) — against two kinds of trace data: a synthetic trace built in-process to mirror the `wm` writer's format ([tests/conftest.py](tests/conftest.py)), and real trimmed traces recorded by the actual `wm` training loop ([tests/fixtures/](tests/fixtures)). The split exists so the fast, deterministic unit tests don't depend on real training runs, while a smaller contract test ([tests/test_fixtures_real.py](tests/test_fixtures_real.py)) still checks that `wmviz` correctly parses what `wm` actually writes.

### How it fits into the larger codebase

This is the only consumer of `wmviz`'s public API from outside the package itself, and the only place the CLI is invoked end-to-end (via Typer's `CliRunner`). Because `wmviz` has no direct dependency on `wm` or `minigrid`, this directory is also where the format contract between the two repos is pinned down in code: [tests/conftest.py](tests/conftest.py)'s `TraceBuilder`/`make_episode` construct `index.csv` rows and `.npz` episode files by hand, matching the schema documented in `wm/docs/superpowers/specs/2026-09-09-run-visualization-design.md` §1 and referenced from [wmviz/trace/reader.py](wmviz/trace/reader.py). If that spec changes, both this synthetic builder and the real fixtures under `tests/fixtures/` need to be regenerated to match.

### Core Implementation

**Synthetic fixtures ([tests/conftest.py](tests/conftest.py))**: `doorkey_layout()` hand-encodes a 7x7 MiniGrid DoorKey-like grid (walls, a locked yellow door at `(3,3)`, a yellow key at `(1,3)`, a goal at `(5,5)`). `make_episode(...)` builds the full set of `.npz` arrays (`actions`, `rewards`, `agent_pos`, `agent_dir`, `carrying`, `door_pos`, `door_open`, optional `obs`) plus a `meta` dict with `format_version=1`. `TraceBuilder` writes these to disk as `trace/episodes/ep_NNNNNN.npz` and appends a matching row to `trace/index.csv`, computing `unique_cells`/`coverage_pct`/`first_key_step`/`first_door_step`/`first_goal_step`/`layout_hash` (a truncated SHA1 of the layout array) the same way the real writer would. The `run_dir` fixture builds a 7-episode run (`p2e-doorkey6x6-s0`) spanning `train_explorer`, `train_task`, `eval` (three episodes, two sharing seed 1000), `coverage_eval`, and one `dream` episode (`make_episode(dream=True)`: constant-valued `obs`, `recon_frames` and `dream_frames` at distinct grey levels, `dream_start = 2`, and more dream frames than real steps so the "past the stored frames" and "longer than the episode" paths are covered) — its episode indices (0–6) and their phase/actor/seed/success values are referenced directly by assertions across [tests/test_reader.py](tests/test_reader.py), [tests/test_selectors.py](tests/test_selectors.py), [tests/test_cli.py](tests/test_cli.py), [tests/test_preview.py](tests/test_preview.py) and [tests/test_dream.py](tests/test_dream.py) — the episodes were deliberately designed to cover distinct selector/filter cases (e.g. episode 3 is the only success and has the most unique cells; episode 4 is the explorer's latest episode; episodes 2 and 5 share seed 1000; the dream episode is placed at step 250 so episode 5 at step 300 stays the `--latest` pick and the milestone tests are unaffected). An autouse `_wide_terminal` fixture pins `COLUMNS=200` via `monkeypatch` so Rich doesn't truncate wide CLI tables when stdout isn't a real tty under `CliRunner`.

**Real fixtures ([tests/fixtures/](tests/fixtures))**: `doorkey6x6/` and `multiroom-n4s5/` are each a `trace/` directory (`index.csv` + `episodes/*.npz`) trimmed from real `wm` training runs of `MiniGrid-DoorKey-6x6-v0` and `MiniGrid-MultiRoom-N4-S5-v0`, produced with `plan2explore` exploration. They were generated by running `wm`'s `train_dreamer.py` into a scratch log dir, then trimming with [scripts/trim_trace.py](scripts/trim_trace.py) to keep only the first 4 training episodes plus every eval/coverage episode. Full provenance commands and fixture contents are recorded in `tests/fixtures/README.md` (not covered by this docs.md — see that file directly). [tests/test_fixtures_real.py](tests/test_fixtures_real.py) is the contract test: it loads both fixtures' `Index` and every `Episode` in them, checks shape invariants (`agent_pos` has `length + 1` rows, `door_open` matches `door_pos` width), and asserts `MultiRoom-N4-S5` actually has 6 rooms per episode despite the "N4" in its env id — an upstream MiniGrid naming quirk documented in both the test and `tests/fixtures/README.md`. It also runs the CLI's `list`/`pick`/`show` commands against these real fixtures. A third fixture, `dream-doorkey6x6/`, holds only `phase=dream` episodes recorded with `wm`'s `--dream-actor both` (a `task` and an `explorer` dream at each video milestone); its contract test checks the dream block's shape invariants (`recon_frames` has `dream_start` rows, frames match `obs` in size) and that `dream_panels`/`compose_frame` composite a real dream frame.

**`scripts/trim_trace.py`**: a standalone script (not part of the `wmviz` package, no test coverage of its own) used only to produce the fixtures above. Given a source run dir, destination dir, and a training-episode cap `n_train`, it copies every non-`train_*` episode plus the first `n_train` `train_*`-phase episodes (matched by `phase.startswith("train_")`), rewriting a trimmed `index.csv` alongside the copied `.npz` files.

**Unit tests, no Blender required**: [tests/test_reader.py](tests/test_reader.py) covers `Index`/`Episode`/`Layout` loading, `parse_ref`, `find_runs`, and the `format_version` mismatch rejection (constructing a bad `.npz` by mutating a loaded fixture's `meta` and re-saving). [tests/test_selectors.py](tests/test_selectors.py) covers `apply_filters`, `sort_rows`, `pick` (all seven selectors), and `NoMatch`/`ValueError` messages. [tests/test_preview.py](tests/test_preview.py) checks `ascii_map`'s exact character grid (including that the end marker overwrites the goal marker when the agent ends on the goal cell) and that `save_png` produces a non-trivial file (skipped via `pytest.importorskip` if matplotlib isn't installed). [tests/test_aggregate.py](tests/test_aggregate.py) covers `visit_counts`/`cumulative_visit_counts`, `same_layout`'s `LayoutMismatch`/`--force` escape, and `nearest_to_milestones`. [tests/test_compose.py](tests/test_compose.py) covers the PIL post-processing primitives (`hstack`/`vstack`/`grid`/`label`/`hud`/`pip`/`split`/`strip`, `to_rgb`'s alpha/greyscale handling) in isolation from any render backend. [tests/test_mpl.py](tests/test_mpl.py) (skipped without matplotlib) covers `figure_image`/`heatmap_image`/`keyframe_steps` and that `preview.save_png` still works via the shared drawing code. [tests/test_cli.py](tests/test_cli.py) drives every CLI command through `CliRunner`, asserting on both stdout content and exit codes (including the exit-code-2 cases for bad selector counts, unknown sort keys, odd `--res`, and cross-layout `timeline`/`heatmap` without `--force`); the `render` command's argument handling is tested without Blender by stopping before the bpy check (its camera default — `fpv` for dream episodes — is captured by monkeypatching the option builder). [tests/test_figures_cli.py](tests/test_figures_cli.py) (skipped without matplotlib) drives `figure`, `timeline`, and `heatmap` end-to-end through `CliRunner` with `--backend mpl`, so the aggregate commands are exercised without Blender. [tests/test_dream.py](tests/test_dream.py) covers the dream path with pixel-level assertions on the synthetic dream episode: the reader's `dream` block, `dream_panels` switching from reconstruction to imagination at `dream_start`, the white-then-black inset border (pip) and divider (split), and that non-dream episodes come out of `compose_frame` byte-identical.

### Things to Know

- The synthetic and real fixtures are deliberately kept separate: the synthetic `run_dir` fixture is the fast/deterministic path used by most tests, while `test_fixtures_real.py` alone exists to catch drift between `wmviz`'s assumptions and what `wm` actually writes on disk.
- `tests/conftest.py`'s inline comment and the module docstring both point back at spec §1 as the source of truth for the trace format — changes to that format need to land in both `wm` and here.
- `pyproject.toml`'s `[tool.pytest.ini_options]` restricts test discovery to `testpaths = ["tests"]` and declares a `slow` marker for tests needing `bpy` or long renders. The Blender tests (`test_scene.py`, `test_animate.py`, `test_cameras.py`, `test_overlays.py`, `test_render.py`) all start with `bpy = pytest.importorskip("bpy")` and `pytestmark = pytest.mark.slow`, call `reset_scene()` first, and read transforms only after `scene.frame_set(...)`, because `matrix_world`/`dimensions` are stale until the depsgraph is evaluated. They run against the real `doorkey6x6` fixture rather than the synthetic run. Not every fixture episode moves — several `doorkey6x6` episodes spin in place for all 360 steps — so tests that need a trajectory (the trail tests) select the first episode whose `agent_pos` changes instead of assuming index 0.
